# ADR 0002 · 本地优先存储（localStorage + IndexedDB 分层）

## Decision

数据默认全部留在设备本地：

- **结构化工作区数据**（含浮光墙缩略图 dataURL）存 `localStorage`，键 `zynthel.workspace.open`，由 Zod schema 校验；
- **大对象**（浮光墙原图、阅读器 PDF/EPUB 文件）存 `IndexedDB`；
- 项目不提供账号体系、不运营后端、不做云同步。跨设备迁移只能靠用户手动导出的备份包。

## Context

产品定位是个人工作台，数据是用户最私密的那一类（任务、日记、密码本）。任何云端组件都会带来：服务端运维责任、数据泄露风险、以及「离线不可用」的体验退化。

同时 localStorage 有容量上限，装不下图片与书籍文件 —— 需要第二层存储。

## Alternatives

- **自建云同步**：功能更强，但要求运营后端与账号体系，与 local-first 定位根本冲突，也会让维护者承担数据保管责任。
- **全部放 IndexedDB**：容量够，但读写为异步且启动时序复杂，小数据频繁读写的体验与可靠性不如同步的 localStorage。
- **SQLite（通过 Tauri 插件）**：结构化查询更强，但会引入原生依赖与迁移成本，而当前数据规模与查询复杂度并不需要。

## Consequences

**优点**

- 无账号、无服务端，隐私面最小，离线可用；
- 单一数据源 + schema 校验，迁移与排障简单；
- 大对象分离后，localStorage 不会被撑爆。

**代价**

- 没有云同步，换设备必须手动导出/导入备份；
- 卸载应用或清除应用数据会导致数据丢失 —— 必须靠文档反复提醒用户先导出备份；
- 存储受 WebView 配额限制，需要靠备份限额与降采样策略兜底。
