# ADR 0004 · AI 仅提供用户自配置入口，不内置密钥与服务

## Decision

Zynthel 的 AI 功能**只提供配置入口**：由用户自行填写 Endpoint（baseUrl）、API Key 与 Model。项目不内置任何服务端点、不内置任何密钥、不提供代理或中转。请求由用户设备直连其配置的服务商（OpenAI 兼容 `/chat/completions`）。

## Context

AI 是可选增强功能，不是 Zynthel 的核心。内置密钥会带来三类问题：

1. **凭据泄露**：随公开仓库与安装包分发的密钥等于公开，且无法回收；
2. **成本外泄**：开发者的付费额度会被所有使用者消耗；
3. **定位冲突**：一旦内置服务，项目就不再是纯 local-first，维护者还要承担服务可用性与合规责任。

## Alternatives

- **内置开发者密钥（按量付费）**：体验开箱即用，但等价于公开分发凭据，且产生持续成本与滥用风险。
- **自建中转 API**：可隐藏密钥，但等于运营后端，与 local-first 及「不收集用户数据」的承诺直接冲突。
- **完全不做 AI**：最省事，但用户失去一项高频需求。

## Consequences

**优点**

- 无任何凭据可泄露，仓库与安装包都是干净的；
- 用户可接入任意兼容服务，自主可控；
- 不使用 AI 时，其余功能完全不受影响。

**代价**

- 用户需要自己准备接口与密钥，上手有门槛；
- 密钥存于本机应用存储（非操作系统密钥库），必须在文档中如实说明这一保护级别；
- 项目无法对第三方服务的可用性、计费与合规负责 —— 已在文档与免责声明中写明。

## Contributors

- 约束提出与决策：项目作者
- 实现：AI 辅助开发，无法从现有记录可靠区分单一来源
- 安全审查：URL 严格校验（仅 http/https + 合法 host）、60 秒超时、CSP `connect-src` 收紧
